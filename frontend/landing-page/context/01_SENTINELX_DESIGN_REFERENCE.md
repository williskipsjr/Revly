# REVLY — LANDING PAGE DESIGN DIRECTION

## 01. CORE DESIGN PRINCIPLE

Revly's landing page should NOT look like a generic AI/SaaS landing page.

The visual direction should be a close stylistic adaptation of the SentinelX landing page:

https://sentinelx-neon.vercel.app/

Study the SentinelX page carefully before implementing anything.

We are NOT copying its content, branding, logo, illustrations, or exact wording.

We ARE adopting its visual language:

- editorial
- technical
- restrained
- monochromatic
- information-dense without feeling cluttered
- highly intentional typography
- thin structural borders
- large statement-driven sections
- progressive disclosure through scrolling
- interactive system visualizations
- evidence presented through metrics and states
- minimal decoration
- almost no conventional SaaS marketing patterns

The result should feel like a serious technical product / research system that happens to have an exceptionally polished website.

Revly should feel like a financial infrastructure company, NOT an "AI startup template."

---

# 02. SENTINELX VISUAL LANGUAGE TO FOLLOW

The SentinelX reference uses a very specific visual philosophy.

### DO

- large amounts of empty space
- black / near-black backgrounds
- off-white typography
- subtle gray borders
- restrained gray secondary text
- tiny uppercase metadata labels
- compact technical annotations
- editorial-style headlines
- asymmetric layouts
- full-width sections
- thin horizontal rules
- small system-status indicators
- data presented as part of the design
- technical diagrams / system states
- terminal-like or system-like UI fragments
- scroll-driven storytelling
- subtle transitions
- strong hierarchy between headline / explanation / evidence

### DO NOT

Do NOT turn the page into:

- a glowing cyberpunk website
- an AI landing-page template
- a gradient-heavy SaaS website
- a glassmorphism dashboard
- a purple/blue neon interface
- a giant hero illustration
- a collection of floating cards
- excessive rounded cards
- excessive shadows
- excessive blur
- excessive animations
- decorative 3D objects
- stock illustrations
- generic AI imagery
- "powered by AI" visual clichés

The sophistication should come from:

TYPOGRAPHY + SPACING + COMPOSITION + INFORMATION + MOTION

—not decoration.

Do NOT use the previously proposed:

"dark navy + electric blue + violet everywhere"

Instead, use SentinelX's restrained monochrome approach as the foundation.

## Accent

Revly may use ONE restrained brand accent derived from the Revly logo.

The Revly logo contains a blue → cyan → violet transition.

Do NOT turn this into a site-wide gradient system.

Instead:

- use the logo's actual gradient only where branding requires it
- use the accent sparingly for active states
- use it for tiny indicators
- use it for selected metrics
- use it for important interactive states
- use it for very subtle visualization highlights

The majority of the website should remain monochrome.

### Accent philosophy

Think:

90–95% monochrome
5–10% Revly accent

NOT:

50% blue
30% purple
20% black

The accent should feel like a signal appearing inside an otherwise controlled financial system.

---

# 04. COLOR BEHAVIOUR

The site should feel almost black-and-white at first glance.

When the user scrolls and reaches important moments, the Revly accent can appear.

For example:

NORMAL

gray text
gray borders
black background

↓

RISK DETECTED

small blue indicator

↓

RECOVERY OPPORTUNITY

accent becomes slightly more visible

↓

ACTION

accent highlights the relevant system state

↓

RECOVERED

strong but still controlled accent state

This makes the color meaningful.

Color should communicate STATE, not decoration.

---

# 05. TYPOGRAPHY

Typography is one of the most important parts of the SentinelX aesthetic.

Use a modern grotesk / neo-grotesk sans-serif for the primary interface.

Preferred direction:

Inter / Geist / similar modern grotesk

The exact font can be selected based on availability, but it must feel:

- neutral
- modern
- technical
- clean
- highly legible
- slightly editorial

Avoid:

- futuristic fonts
- sci-fi fonts
- overly geometric startup fonts
- display fonts
- rounded playful fonts

---

## HEADLINES

Large headlines should be:

- bold
- tight
- confident
- editorial
- relatively short

Example:

"Revenue disappears quietly."

Then:

"Revly finds where it leaks."

Do NOT write huge marketing paragraphs in the hero.

The headline should create curiosity.

---

## BODY

Body text should be:

- relatively small
- relaxed line-height
- gray/off-white
- constrained to readable widths

Do not make every section visually loud.

---

## SYSTEM LABELS

Use tiny uppercase labels for technical information.

Examples:

REVENUE RECOVERY
PAYMENT INTELLIGENCE
RECOVERY SIGNAL
MERCHANT STATE
INTERVENTION
RECOVERED
FAILED PAYMENT
RETRY WINDOW

These labels should feel like system annotations.

Use:

- small font size
- letter spacing
- uppercase
- muted gray

---

# 06. TYPOGRAPHIC HIERARCHY

Use a strong hierarchy.

Example:

EYEBROW
small uppercase / muted

↓

HERO HEADLINE
very large / strong

↓

SUPPORTING COPY
medium / gray

↓

ACTION
small / controlled

↓

SYSTEM EVIDENCE
tiny / technical

Do NOT make every element bold.

The page should breathe.

---

# 07. LAYOUT PHILOSOPHY

Do not use a conventional:

Navbar
Hero
3 cards
Features
Testimonials
Pricing
CTA

structure.

Instead, build the page as a STORY.

The user should feel like they are moving through the Revly system.

Think:

OBSERVE
→ UNDERSTAND
→ DETECT
→ DECIDE
→ INTERVENE
→ RECOVER
→ PROVE

Each section should reveal another layer of the system.

---

# 08. SPACING

Use generous negative space.

Large sections should have significant vertical breathing room.

Do not compress information simply because there is empty space.

Empty space is part of the design.

The SentinelX reference frequently allows individual statements, diagrams and system states to exist independently rather than filling every pixel.

Replicate that philosophy.

---

# 09. BORDERS

Use thin borders extensively.

But keep them subtle.

Preferred:

1px solid #242424

or

1px solid rgba(255,255,255,0.08)

Borders should create structure without looking like card containers everywhere.

Prefer:

SECTION DIVIDERS
SYSTEM DIAGRAM LINES
TABLE/RUNNER LINES
METRIC SEPARATORS
TIMELINE LINES

Avoid:

large rounded cards with thick borders

---

# 10. BORDER RADIUS

Keep radius restrained.

Most structural elements should have:

0px
2px
4px

Avoid excessive:

12px
16px
24px
32px

rounded cards.

The reference feels more like a technical publication / system interface than a consumer SaaS dashboard.

---

# 11. NAVIGATION

Navigation should be minimal.

Think of the SentinelX navigation:

- brand
- a few section anchors
- compact controls
- no oversized CTA buttons
- no giant pill navigation

The navigation should disappear into the visual system rather than becoming the dominant element.

Possible Revly navigation:

REVLY

Problem
System
Recovery
Intelligence

[Enter Platform]

Keep it extremely restrained.

---

# 12. HERO

The hero should NOT be:

"AI-powered revenue recovery platform for modern businesses."

That's generic SaaS copy.

The hero should start with a provocative business truth.

Possible direction:

"Revenue doesn't disappear at checkout."

Then progressively reveal:

"Sometimes the payment fails."

"Sometimes the retry is wrong."

"Sometimes the customer was ready to pay."

"Revly finds the difference."

The hero should create tension before explaining the product.

---

# 13. HERO VISUAL

Do NOT use a generic hero illustration.

Instead create a technical visualization.

Possible concept:

A payment lifecycle / revenue stream.

Example:

PAYMENT
   ↓
AUTHORIZED
   ↓
FAILED
   ↓
RECOVERY SIGNAL
   ↓
INTERVENTION
   ↓
RECOVERED

The visualization should initially look quiet.

As the user scrolls, individual payment events appear.

Some fail.

Some recover.

The system identifies which intervention is worth taking.

This becomes the visual storytelling mechanism.

---

# 14. SCROLL PHILOSOPHY

Scrolling should reveal the product.

Do not animate everything simply because you can.

Use progressive disclosure.

Example:

At first:

PAYMENT
₹2,499
FAILED

Scroll:

FAILURE REASON
Insufficient funds

Scroll:

CUSTOMER SIGNAL
High recovery probability

Scroll:

NEXT BEST ACTION
Retry in 14 minutes

Scroll:

RESULT
RECOVERED
₹2,499

The animation should make the user understand the product.

Every animation must have a narrative purpose.

---

# 15. MOTION

Motion should feel:

- precise
- slow enough to understand
- technical
- deliberate
- subtle

Avoid:

- bouncing
- excessive parallax
- flashy transitions
- spinning 3D objects
- constant glowing
- spring-heavy UI
- random floating elements

Use:

- opacity transitions
- position interpolation
- number transitions
- line drawing
- state transitions
- progressive reveal
- sticky sections
- scroll-linked diagrams

The SentinelX page uses motion to explain system behaviour.

Revly should do the same.

---

# 17. DATA AS DESIGN

Metrics should be used as evidence.

Do not throw random impressive numbers onto the page.

Every metric must answer:

"Why should I believe Revly?"

Possible evidence:

PAYMENTS OBSERVED
128,421

FAILED PAYMENTS
8,421

RECOVERY CANDIDATES
3,184

INTERVENTIONS
1,206

RECOVERED
₹18.4L

The exact numbers must come from the actual demo / implementation.

Never fabricate impressive-looking production claims.

If numbers are synthetic/demo values, explicitly label them as such where appropriate.

---

# 18. VISUAL TREATMENT OF REVLY LOGO

Use the provided Revly logo exactly.

The logo has the distinctive:

blue → cyan → violet

gradient.

Preserve it.

Do not redesign the logo.

Do not recolor the logo arbitrarily.

Do not add glow around it.

Do not put it inside a giant gradient blob.

On dark backgrounds:

use the colored logo.

On light backgrounds:

use the appropriate monochrome/dark version if provided.

The logo itself should be the primary source of brand color.

---

# 19. BRAND COLOR RULE

The Revly gradient is a BRAND ACCENT.

It is NOT the website background.

It is NOT the default button color everywhere.

It is NOT a giant background gradient.

It is NOT an ambient glow.

It should appear almost like a signal.

That distinction is critical.

---

# 20. OVERALL VISUAL TARGET

The final page should feel like:

"Bloomberg terminal meets modern product engineering meets premium editorial website."

Not:

"AI startup landing page."

Not:

"Cyberpunk dashboard."

Not:

"Web3 website."

Not:

"Dribbble gradient showcase."

The visual personality should be:

QUIET
TECHNICAL
CONFIDENT
PRECISE
SERIOUS
INTELLIGENT

The page should feel expensive because it is restrained.

---

# 21. REFERENCE PRIORITY

When implementing the design, prioritize the SentinelX reference in this order:

1. TYPOGRAPHY
2. SPACING
3. INFORMATION HIERARCHY
4. SECTION COMPOSITION
5. BORDER / GRID SYSTEM
6. SCROLL STORYTELLING
7. SYSTEM VISUALIZATIONS
8. MOTION
9. COLOR
10. DECORATION

Do not compensate for weak layout with gradients or effects.

---

# 22. FINAL RULE

If a design decision makes Revly look more visually impressive but less like SentinelX's restrained technical editorial aesthetic:

DO NOT DO IT.

When in doubt:

REMOVE.

Remove gradients.
Remove shadows.
Remove cards.
Remove decorative elements.
Remove unnecessary animation.
Remove excessive color.

Then strengthen:

Typography.
Spacing.
Hierarchy.
System visualization.
Content.
Motion.

The website should earn attention through clarity and storytelling, not visual noise.
